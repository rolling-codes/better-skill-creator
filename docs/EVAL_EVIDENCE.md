# What makes an evaluation result comparable

- **Keep the baseline independent.** Run the same task, fixtures, and model on each side. Reserve a fresh run for each side and grade after both complete. A blind comparator can compare the two saved outputs without knowing which condition produced each one. [Paired grading](USER_GUIDE.md#grade-paired-authoring-runs) · [Blind comparator](../skills/skill-creator/agents/comparator.md)
- **Keep selection and final scoring separate.** In the default three-way description optimizer, the rewrite model sees training feedback. Validation scores pick the candidate. The optimizer evaluates the held-out cases once, after selection, when the split contains held-out cases and the run can finish. [Description optimization](USER_GUIDE.md#optimize-selection-descriptions) · [Optimizer source](../skills/skill-creator/scripts/run_loop.py)
- **Keep failures visible.** A timeout, authentication failure, or broken discovery control cannot count as a successful negative trigger test. Behavior grading can return `UNDETERMINED` when a transcript cannot support the assertion. [Trigger measurement](USER_GUIDE.md#how-the-measurement-works) · [Behavior verdicts](USER_GUIDE.md#understand-the-verdicts)
- **Compare like with like.** The comparison tools check compatible queries and labels, complete executions, and known trigger thresholds. Front-end comparisons keep exact requested model IDs separate. Aliases can resolve to different models over time. [Comparison rules](USER_GUIDE.md#compare-compatible-runs) · [Model behavior and evidence](MODEL_BEHAVIOR.md)
